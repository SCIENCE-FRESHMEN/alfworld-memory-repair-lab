# ALFWorld Memory Repair Lab：二次开发范围与最小研究方案

## 当前阶段

项目名称为 **ALFWorld Memory Repair Lab**，项目目录与 Conda 环境统一命名为
`alfworld-memory-repair-lab`，对应 ALFWorld 环境下的程序记忆检测与修复研究。

当前工作区保留上游实现与历史实验数据，计划在此基础上扩展自动记忆修复。
该方法尚未实现，没有新增模型实验或性能结论。原有算法与历史实验属于上游工作，
来源与原始引用见 [README.md](../README.md#citation)。

代码使用 ALFWorld 的文字观测和文字动作。`src/alfworld_env.py` 包装文字环境，
`src/agent.py` 执行任务。三维视觉控制不在当前实现和拟议实验的范围内。

## 拟研究的问题

研究“基于行动前置条件的错误程序记忆检测与修复”：将程序记忆中的步骤转换为
带适用条件的候选动作，用执行证据区分条件未满足、步骤本身错误与证据不足，
并检验这种区分能否减少错误记忆对任务规划的干扰。以上是研究计划，效果尚待验证。

优先从 `wiki_v3` 的自然语言程序页与已有轨迹开展离线分析。对 MACLA 程序记忆
开展实验时，需要另行解决未随仓库分发的 `MACLA.py` 依赖，不能宣称已经覆盖。

## 证据与标注约束

- 轨迹中的 `admissible_commands` 对应该条动作执行后的状态。检查动作执行前
  是否可用，应对齐上一状态的命令集合；首步需要明确的初始状态证据。
- 动作暂时不在可执行集合中，只能说明当前状态下不可执行；不能直接证明记忆
  过期或永久错误。缺少对象、尚未到达位置和未满足前置条件都可能造成这种情况。
- 动作可执行也不能证明它能完成目标。检测必须区分可执行性与任务有效性。
- 首先审查各批次日志的字段覆盖率，再确定可评估样本；缺失状态或不可对齐的
  样本标为证据不足，不补造状态、动作或人工标签。
- 上游手工修复案例可用于提出假设，不能当成自动修复已经有效的证据。

## 最小实验设计

| 对照 | 处理方式 |
|---|---|
| 原始记忆 | 使用相同冻结记忆，不修改步骤 |
| LLM 自检 | 对同一记忆和允许访问的证据进行自检，记录修改与调用成本 |
| 可执行条件校验 | 用已定义的状态证据检查适用条件，区分暂不可用与有证据支持的错误 |

固定任务子集、记忆快照、模型版本、提示、采样参数、预算和任务顺序。检测规则和
修复策略只能在开发集确定；评测集保留用于最终比较。人工标注应给出明确规则，
并记录分歧和不确定样本。

离线阶段报告字段覆盖率、可判定率和经人工核验的检测准确性；缺少可靠错误标签时
不计算或宣称检测精度。在线小规模实验再报告配对任务成功率、无效动作、额外
模型调用、延迟和修复副作用，并报告样本量及不确定性。离线重放无法独立证明
修改记忆后的任务成功率提升，仍需实际执行验证。

## 算力与接口边界

已有日志可以先用普通 Python 分析。上游 README 和运行元数据记录了 L40S GPU；
离线分析可运行不代表完整原始实验在 CPU 上得到等效复现。

`src/llm.py` 已有面向 Ollama 的 OpenAI 兼容客户端。其他模型 API 的参数兼容性、
凭据管理、嵌入接口、预算和成本仍需单独适配验证，本阶段未完成这项工作。
后续若使用 API，应先做限定样本与调用预算的试验，再决定是否扩大规模。
